🏗️ Arquitetura do Sistema

Sistema de Análise de Sentimentos em Tempo Real

📊 Fluxo de Dados
📱 Cliente
Postman / HTTP
Envia requisições REST
⬇️
🌐 API Flask
POST /api/analyze
Cadastra análise
GET /api/result/:id
Busca resultado
GET /api/status
Status da fila
⬇️
⚙️ Fila de Processamento
Queue (Python)
Tarefas pendentes
⬇️
⚡ Worker
Processador
Análise de sentimentos
⬇️
💾 Banco de Dados
SQLite
2 schemas (users, analyses)
🔧 3 Funções Principais
1️⃣
cadastrar_analise()
• Gera UUID único
• Salva no banco
• Adiciona na fila
• Retorna ID da análise
2️⃣
processar_fila()
• Pega tarefa da fila
• Analisa sentimento
• Calcula score (-1 a +1)
• Atualiza banco
3️⃣
buscar_resultado()
• Consulta banco pelo ID
• Retorna análise completa
• Status, sentimento, score
• Texto original
🗄️ 2 Schemas do Banco
👥 users
id: INTEGER (PK)
email: TEXT (UNIQUE)
password_hash: TEXT
created_at: TIMESTAMP
📊 analyses
id: TEXT (PK, UUID)
user_id: INTEGER (FK)
text: TEXT
sentiment: TEXT
score: REAL (-1 a +1)
status: TEXT
created_at: TIMESTAMP
🔄 Fluxo Completo
1
Cliente envia POST com texto para análise
2
API chama cadastrar_analise() - Salva no banco com status "pending"
3
Tarefa é adicionada na fila de processamento
4
Worker pega tarefa da fila
5
Worker chama processar_fila() - Analisa sentimento do texto
6
Resultado salvo no banco com status "completed"
7
Cliente faz GET para buscar resultado
8
API chama buscar_resultado() - Retorna análise completa
